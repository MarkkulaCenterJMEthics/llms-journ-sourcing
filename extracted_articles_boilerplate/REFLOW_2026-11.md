# Re-flow of hard-wrapped story texts to one paragraph per line (November 2026)

Run on 2026-11-02 with `reflow_wrapped_text.py` (repo root). Tracked as item 64 in `development-of-v59.md`.

## Why

`v10-extract-multiple-LLMs.py` sends each story's body to the models exactly as it is in this folder (`article_body()` only drops the header). So **the line breaks in each `.txt` are the paragraph structure a model sees.**

Two kinds of files live here:

- **One paragraph per line** (113 files, mostly fetched from the web). Paragraphs are already marked, and they follow the page's own paragraphs, which is what the annotators saw.
- **Hard-wrapped** (53 files, converted from PDFs). Each line is cut at the PDF's line width, so a paragraph break looks like any other line break.

A check against the source PDFs (2026-11-02, the 47 wrapped files with a PDF on disk) found that of the PDFs' 920 paragraph breaks, only 5% were marked by a blank line in the text, 74% could be guessed from a short previous line, about 19% were invisible (the previous line ran nearly full width), and 1% fell in the middle of a line. On top of that there were 63 false breaks: blank lines left by PDF page breaks in the middle of a sentence.

That matters because **GT Sourced Statements are one row per source per paragraph** (`gt-migration-methodology.md`, the Sourced Statement extraction rule), and during Phase 4 rows were split at the PDF's paragraph breaks (stories 54 and 62). A model reading the wrapped text couldn't see some of those breaks and saw breaks that weren't there, which would show up as Sourced Statement boundary mismatches that aren't the model's fault. After the re-flow, all 166 story texts mark paragraphs the same way.

## What changed

Only whitespace. For every file, the script checks that every non-space character of the body is unchanged and in the same order, and refuses to write otherwise. The header block (between the `=====` lines) is untouched. Inside the body, the wrapped lines of each paragraph are joined into one line (with a space, or with nothing after a line-final hyphen), and PDF page-break blank lines are dropped. Photo captions, credit lines and labels such as "Image" stay as their own lines, as the PDF lays them out. The original line-by-line layout is in git history.

## How paragraph breaks are found

Each text line is matched to its line in the PDF, in order. PDF lines with no counterpart in the text (browser headers and footers, site navigation, page numbers, ads already removed from the text) are skipped. Doubled "faux-bold" glyphs are removed first, as in `storypdf_to_text.py`.

Thresholds come only from the lines that matched the article text: the body font size is the most common size among them, and the normal within-paragraph line gap is the most common gap between consecutive body lines on a page.

A new paragraph starts when:

- the gap to the previous line is more than 1.5 × the normal gap + 1.5pt;
- the font size changes (title, byline, caption, label); or
- at a page break, the last line on the previous page was short.

A sentence is never split: a line still continues the paragraph if it starts with a lowercase letter, or the line before ends in a comma or hyphen, or the line before ran nearly full width without closing punctuation. This guard doesn't override a font-size change (that's what keeps captions separate) unless the break is plainly mid-sentence (a lowercase word before and a lowercase start after, or the text so far ends on "the", "of", "and" and similar), and it doesn't apply to a short label such as "Image". A text line with no PDF match, and the line after it, is placed by punctuation instead: a new paragraph only if the text so far ends a sentence and the next line starts one.

### How the rules were arrived at

The first pilot (story 54) used one gap threshold for each whole PDF. It merged the title with the byline (different font sizes) and glued paragraphs that start at the top of a page onto the previous paragraph, because the browser's page footer was being read as the last line. Matching text lines to PDF lines and using font-size changes fixed both.

Running all 47 files then showed:

- Five files with many unmatched lines: 197's PDF prints every glyph twice (fixed with glyph de-duplication), and 72, 157, 181 and 195 open with long stretches of site navigation (fixed by searching the whole PDF, not a short window).
- Some layouts (191, 151, 203, 206, 209) under-split, because a threshold computed from all lines, navigation and small print included, came out above the real paragraph gap. Fixed by taking thresholds from the matched lines only.
- About ten paragraphs broken mid-sentence at a page break or a font change (e.g. 165 "...reliance on the / United States", 72 "...a 15-year South / Shore resident"), which led to the never-split-a-sentence guard. A first version of that guard also joined lists of names (98), credit lines and labels whenever the line ended in a lowercase letter; that test was dropped.
- One case where a single unmatched line made the next line's gap be measured from two lines back (72); now the line after an unmatched line is placed by punctuation.

The final run has no paragraph ending mid-sentence (lowercase or comma end followed by a lowercase start, or an end on a function word).

## Re-running

```
python reflow_wrapped_text.py extracted_articles_boilerplate/<story>.txt <source>.pdf           # print the re-flowed body
python reflow_wrapped_text.py extracted_articles_boilerplate/<story>.txt <source>.pdf --write   # replace the file
```

The source PDFs used are listed in the per-file table; they are kept outside the repo (`~/Documents/GT-II-finishedfiles-XLSx/story-texts (PDFs and text)/` and `~/Documents/GT-II-finishedfiles-XLSx/`). Run the script on the original wrapped text (from git history, before commit for this re-flow), not on an already re-flowed file: its paragraph lines no longer line up with the PDF's lines, so a second pass would re-decide breaks it shouldn't.
